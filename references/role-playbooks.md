# 各岗位简历打法（Playbook）

同一个项目、同一套事实，**按目标岗位换侧重与排序**。本文件给出每个岗位的：定位语、技能排序、职责句式、亮点选择、必答题库、常见坑。

> 通用原则：**事实不变、措辞分档、排序变化**。跨岗位复制后必须删掉与本岗位无关的内容。

---

## 一、后端 / 服务端

**定位语**：`X 年后端经验，负责 <核心链路>，支撑 <规模>；关注 <一致性/性能/稳定性>。`

**技能排序**：语言与框架 → 数据库与数据层 → 中间件与分布式 → 工程化与稳定性 → 领域集成（支付/消息/搜索…）

**职责句式**（动作 + 技术 + 场景 + 结果）：
- 负责 X 链路开发：基于 A + B 完成 C，实现 D
- 主导 X 方案落地：以 A 解决 B 问题（附证据）
- 处理线上问题：定位并修复 X（附证据）

**亮点优先选**：MQ 可靠性（不丢不重）、分布式锁与幂等、分库分表与路由、索引与慢查询、连接池/线程池治理、缓存设计、线上故障复盘。

**必答题库**
- 事务：传播行为与失效场景、本地消息表 vs 事务消息、事务与 MQ 发送时序
- 数据库：索引原理与 explain、锁类型与隔离级别、MVCC、死锁定位与规避、分表后跨库分页与全局 ID
- 并发：线程池 7 参数与隔离、JMM、CAS、AQS
- JVM：内存分区、GC 选型、OOM 与 native mmap 失败、线上诊断工具
- 中间件：MQ 顺序/重复/积压、Redis 持久化与集群、缓存穿透击穿雪崩
- 架构：分布式事务方案对比、限流熔断降级、容量反推
- 排查方法论：一个接口变慢，你怎么查？

**坑**：只罗列技术名不写场景；把「用过」写成「设计」；没有量化还硬写百分比。

## 二、前端

**定位语**：`X 年前端经验，负责 <系统/端> 的页面架构与性能优化，覆盖 <页面数/用户量>。`

**技能排序**：框架（React/Vue/…）与语言（TS）→ 工程化（构建/规范/CI）→ 状态管理与路由 → 性能与体验 → 跨端/小程序

**亮点优先选**：页面与组件规模、状态管理重构、构建/打包优化（体积、首屏）、性能指标（LCP/INP/CLS，**必须实测**）、SSR/SSG、组件库与设计系统、埋点与监控、i18n、复杂交互（拖拽/虚拟列表/富文本/图表）。

**必答题库**
- 语言：TS 泛型与类型体操（适度）、`this`、事件循环与微任务、闭包与内存
- 框架：响应式原理（Vue3 Proxy / React Fiber）、diff 与 key、Hooks 依赖与闭包陷阱、状态管理选型
- 性能：首屏优化清单、懒加载与预加载、长列表虚拟化、重排重绘、缓存策略、CDN
- 工程化：Webpack/Vite 差异与优化、Tree-shaking、monorepo、npm/pnpm 依赖治理
- 浏览器：跨域与 CORS、Cookie/SameSite、存储方案、安全（XSS/CSRF）
- 小程序/跨端：双线程模型、分包、原生能力限制

**坑**：写"优化了性能"但没有指标；把后端能力写进前端版本；忽略兼容性与异常兜底。

## 三、全栈

**定位语**：`X 年全栈经验，独立负责 <模块/产品> 从接口到页面的完整交付。`

**技能排序**：一条完整链路的证据（前端 + 接口 + 数据）→ 工程化与部署 → 协作与规范

**亮点优先选**：端到端交付（一个人做完某功能）、接口契约设计、BFF/聚合层、SSR 数据流、前后端联调与 Mock、部署与运维。

**必答题库**：上面两套的**交集**，外加：接口鉴权方案、跨端数据一致性、SSR 缓存与降级、如何保证前后端契约不漂移。

**坑**：两边都写但都不深；没有"独立交付"的实证。

---

## 四、移动端（原生/Flutter/RN/小程序）

**定位语**：`X 年移动端经验，负责 <App/小程序> 的 <模块>，覆盖 <DAU/装机量>。`

**技能排序**：平台与语言 → UI 与架构（MVVM/组件化）→ 性能与稳定性（启动/内存/崩溃）→ 发布与灰度

**亮点优先选**：包体积优化、启动耗时、崩溃率与 ANR、内存与卡顿、热修复/动态化、渠道打包与灰度、离线缓存、推送、原生桥接。

**必答题库**：生命周期与内存泄漏、线程与主线程卡顿、列表复用与图片加载、网络层与重试、权限与隐私合规、热更新边界、多端一致性。

**坑**：没有线上指标（崩溃率/启动耗时）；把"会写页面"写成"负责架构"。

## 五、数据 / 算法 / AI 应用

**定位语（数据）**：`X 年数据开发经验，负责 <数仓/管道>，日均处理 <数据量>。`
**定位语（AI 应用）**：`X 年后端 + AI 应用经验，落地 <LLM 能力>，覆盖 <调用量/场景>。`

**技能排序（AI 应用）**：LLM 接入与编排 → 上下文与会话 → 检索增强（RAG）→ 工程化（流式/并发/成本/降级）→ 评测与安全

**亮点优先选（AI）**：真实上线的 LLM 场景（提示词/编排/工具调用）、流式输出与首字延迟、会话与记忆、RAG 链路（切分/embedding/检索/重排/引用）、评测集与指标（命中率/幻觉率/拒答率）、成本控制（token 预算/缓存/路由）、安全（注入/越权/合规）。

**必答题库（AI）**
- 概念：Agent 五要素、ReAct vs Plan-Execute、RAG vs 微调 vs 长上下文
- 检索：切分策略、embedding 选型、混合检索与 rerank、recall@k/precision
- 工程：并发与限流、超时重试降级、流式 vs 非流式、会话存储
- 评测：评测集构建、LLM-as-judge、A/B、失败案例分析
- 成本与安全：token 计量、缓存与路由、prompt injection、数据隔离
- **必须诚实**：没做过就说没做过，给"如果我来做"的落地计划

**坑（最容易翻车）**：把"调了 API" 写成 "Agent 平台"；声称 RAG 但没有向量库依赖；用量极小却说"大规模应用"；没有评测却声称效果提升。

## 六、测试 / QA

**定位语**：`X 年测试经验，负责 <系统> 的质量保障与自动化，覆盖 <用例数/自动化率>。`

**技能排序**：测试设计（等价类/边界/场景）→ 自动化（接口/UI/性能）→ 质量门禁与 CI → 缺陷管理与复盘

**亮点优先选**：自动化框架搭建与覆盖率、接口/UI 自动化、性能压测（含指标）、CI 门禁、Mock 与测试数据、线上问题主动发现（监控告警）。

**必答题库**：测试用例设计方法、接口测试与断言策略、UI 自动化稳定性、压测指标（TPS/RT/错误率）与瓶颈定位、缺陷分级与生命周期、如何推动质量改进。

**坑**：只写"负责测试"，没有工具/框架/覆盖率证据。

---

## 七、运维 / SRE / DevOps

**定位语**：`X 年运维/SRE 经验，负责 <系统> 的部署、监控与稳定性，SLA <指标>。`

**技能排序**：容器与编排 → CI/CD → 可观测性（日志/指标/追踪）→ IaC → 容量与应急

**亮点优先选**：CI/CD 流水线（阶段与耗时）、容器化/K8s 编排、监控告警体系与降噪、故障应急与复盘、容量规划与压测、成本优化、安全加固。

**必答题库**：K8s 核心对象与调度、探针与滚动发布、资源与限流、常见故障（OOM/磁盘/端口/证书）排查、监控指标选型（RED/USE）、SLO/错误预算、灰度与回滚。

**坑**：把开发做的事写成运维成果；没有 SLA/指标。

## 八、通用软技能题库（所有岗位都会被问）

| 问题 | 应答骨架 |
|---|---|
| 自我介绍 | 年限 + 方向 + 一个最有分量的成果 + 与岗位的匹配点（30–45 秒） |
| 最有成就感的项目 | 背景 → 你的动作 → 难点 → 结果（带数据） |
| 最大的技术难点 | 现象 → 定位过程 → 方案取舍 → 验证 |
| 为什么离职 | **只讲成长空间与流程诉求**，不评价任何人（详见离职话术） |
| 为什么选我们 | 业务/技术/团队三点，各一句，能落到对方产品上 |
| 3–5 年规划 | 技术纵深 + 业务理解 + 影响力（带人/开源/规范） |
| 期望薪资 | 先反问区间与职级；必须报就给区间（当前总包 × 1.3–1.5 作为下沿） |
| 遇到过的冲突 | STAR：技术分歧用数据说服，不涉及人身 |
| 到岗时间 | 诚实 + 可协商 |
| 你最大的短板 | 真实 + 正在怎么补（**不要说"我太追求完美"**） |
