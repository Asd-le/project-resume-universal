# 跨栈踩坑清单（Universal Pitfalls）

> 全部来自真实项目实践（本文件是"血泪清单"，每条都实际坑过一次）。换项目分析前扫一遍，能省几小时。

---

## 一、编码与文件格式（最容易让工具整个失效）

| 坑 | 表现 | 正确做法 |
|---|---|---|
| **PowerShell 脚本不带 BOM** | Windows PowerShell 5.1 按 ANSI 解码中文 → 大批 `ParserError`，脚本完全不可执行 | `*.ps1` 一律 **UTF-8 with BOM** |
| **SKILL.md 带 BOM** | 技能发现器读到首行不是 `---` → **技能从会话目录消失** | `SKILL.md` 必须 **UTF-8 无 BOM** |
| **`Get-Content` 读中文源码** | 5.1 默认 ANSI，个别文件抛异常使内容变 `$null`，后续正则全部失效 | 用 `[System.IO.File]::ReadAllText($p, [Text.UTF8Encoding]::new($false))` |
| **CRLF/LF 混用** | Bash 脚本出现 `$'\r': command not found` | `.sh` 用 LF；`.ps1` 用 CRLF；跨平台传递前先规范化 |
| **文本里混入控制字符** | Markdown 里出现 NUL / 裸 CR → 解析或渲染异常 | 处理前扫 `\x00` 与"非行尾 CR"，批量替换要按字节验证 |
| **批量替换造成字符损坏** | 例如"应用"→"用用"、"主导"→"服导"（替换片段落在多字节字符中间） | 替换后**必须全量扫描**关键词复核；对中文不要用过短的模式 |

## 二、脚本健壮性（让采集器"静默产出空结果"的原因）

| 坑 | 表现 | 正确做法 |
|---|---|---|
| **PowerShell 保留变量** | `$args` 当普通变量名 → 解析报错或行为异常 | 用 `$gitArgs` / `$authorArgs` 等 |
| **方法调用带空格** | `$obj.Add ('x')` 被当成命令调用 → 语法错误 | `$obj.Add('x')` |
| **正则里的引号/方括号** | 单双引号混用、字符类含引号 → 解析器错乱（`Unexpected token ']'`） | 复杂正则用 here-string `@'...'@` 或先赋给变量 |
| **字符串数组用 `-match`** | `@('a','b') -match 'a'` 返回**匹配项数组**而非布尔 → `if` 判定语义错 | 显式 `[bool]("$x" -match $pat)` |
| **同名文件互相覆盖** | 仓库里存在多个 `pom.xml`/`package.json`（含 demo、示例、子模块）→ 字典赋值时后者覆盖前者 | 全部保留并拼接，或按"路径深度"优先取根目录的 |
| **宽松 JSON 解析失败** | `tsconfig.json`/`package.json` 含注释或尾逗号 → `ConvertFrom-Json` 抛错致后续全空 | 用 `try/catch` 包裹并降级为正则提取 |
| **bash 全部 `set +e`** | 失败静默继续，产出空文件被误当"无证据" | 关键取数处显式判 `$?`，并在文档里区分"无数据"与"取数失败" |
| **`awk` 三参 `match($0,re,arr)`** | 仅 gawk 支持，mawk/busybox 解析失败 | 需要捕获组时改用 `sed`/`grep -oE` 或明确要求 gawk |
| **重跑覆盖人工修正** | 采集器重跑会把人工更正过的证据文件覆盖掉 | 人工修正写到**独立文件**（如 `_corrections.md`），或先备份 |

## 三、Git 与归属（决定简历"是不是你的"）

| 坑 | 表现 | 正确做法 |
|---|---|---|
| **只分析工作区** | 工作区可能落后主线数百上千个提交，规模/技术栈/贡献全部失真 | 先 `git rev-list --count HEAD..origin/<最新分支>`，必要时用 `-Branch` 只读分析 |
| **同邮箱多署名** | 同一人改写 `user.name`（如 `zhangsan`→`zs`）被算成两个人 | 按 **email 聚合**，列出"同邮箱多署名"并要求用户确认 |
| **cherry-pick / 多分支重复** | 同一改动在多分支各一次 → 提交量虚高 | 说明口径（`--all` vs 单分支），必要时以单一主线为准 |
| **把团队模块算成个人** | 面试追问即崩 | 逐个核对作者：本人做了哪几家/哪几个模块，团队做了哪些 |
| **用 `checkout` 修工作区** | 会破坏用户未提交的改动 | 一律 `git <ref>:<path>` 只读读取，**禁止** `checkout/reset` |

## 四、配置与运行期（"配置里写了"≠"实际生效"）

| 坑 | 表现 | 正确做法 |
|---|---|---|
| **profile 覆盖** | 基础配置写 800，profile 里写 200 → 实际 200（曾有文档把 800 当生效值） | 核对 `spring.profiles.include/active` 链、`application-<profile>.yml`、外部 `config/` 目录、启动参数 `-D` |
| **依赖存在≠生产启用** | pom/package.json 里有，但代码无使用痕迹 | 标注 `[INFERRED] 已引入未使用`，列入待确认 |
| **开发环境值当生产值** | 读到 `application.yml`（active=local）就下结论 | 明确以 prod/production 配置为准，找不到就标注 |
| **脱敏后仍泄漏** | 敏感词在冒号之后（如 `encryptor:`、`-Dxxx.password=`) → 按键名脱敏不命中 | 用**整行匹配**：命中敏感词即丢弃整行（注释行也丢）；并对产物做一次 `grep` 自检 |
| **原始输出绕过脱敏** | 直接落盘的命令输出（`*raw*.txt`）含明文口令 | raw 文件单独扫描，或采集时即脱敏 |

## 五、数据与指标（简历数字的可信度）

| 坑 | 表现 | 正确做法 |
|---|---|---|
| **估算值当精确值** | `information_schema.TABLE_ROWS` 与 `COUNT(*)` 可差 20%+ | 同时标注"估算 X / 精确 Y"，不要混用同一口径 |
| **统计口径未写清** | 同一指标在两个文件里数值不同（过滤条件不同） | 数字必须带**来源文件 + 过滤条件** |
| **口径漂移未说明** | 分支快照 54 张表 vs 生产实测 65 张表（滚动建表增长） | 两者都写，并说明"为何不同、何时采集" |
| **指标归属错位** | GC 统计来自重跑后的新实例，被写成故障当天 | 每个指标标注**数据窗口**；无数据就写"取证缺口" |
| **中间产物未归档** | 结论依赖 `/tmp/xxx.txt`，事后无法复验 | 关键中间产物归档到输出目录，并在文档写明命令与输入文件 |
| **分母缺失导致夸大** | "日均 13–20 QPS、峰值 459 QPS" 不说明是全天平摊 | 补峰谷比或说明统计窗口 |
| **自相矛盾的内部数据** | 总量 578 万行，但分类桶合计仅 3.3% | 交付前做一次**内部一致性校验**；冲突处标注"不可复验" |

## 六、结论与表述（面试官会当场抓的点）

| 坑 | 表现 | 正确做法 |
|---|---|---|
| **单一技巧当通用结论** | 把某一次死锁的解法写成"多次死锁的共性根因" | 逐次列事实，方法论与个例分开写 |
| **推断写成事实** | "线程池被打满"无采样证据却写在 `[CONFIRMED]` 标题下 | 加 `【推断】` 标记，或移入取证缺口 |
| **年限/身份自相矛盾** | "7 年累计提交"与"5 年经验"并存 | 仓库年限与个人年限分开表述 |
| **管理语义夸大** | "带 5 人团队"但用户实际"不带人" | 统一为"团队 N 人，本人负责核心链路与线上兜底（非管理岗）" |
| **未证实的工具链** | 写"自动对账系统"，实际只有人工比对 | 写清"系统具备 A，当前流程是 B，代码里没有 C" |
| **测试/质量夸大** | "已补关键链路测试"但只有 3 个 `@Test` | 如实写"补了少量回归用例，整体尚无测试体系" |
| **跨岗位串味** | 前端版本里出现分库分表细节 | 每个岗位版本裁剪后复核 |

## 七、安全与合规（每次都要做）

1. **输出目录必须加 `.gitignore`**（`.project-resume/`、`.dsh/`），尤其仓库是公司项目时；
2. **凭据轮换优先于删除**：源码里硬编码的密钥即使删掉，Git 历史仍可检出 → 必须轮换；
3. **SSH 私钥用完即撤**：从服务器 `authorized_keys` 移除公钥，并删除本地私钥；
4. **PII 检查**：日志/证据里可能含真实姓名、手机号、订单号、身份证 → 外发前人工脱敏；
5. **不要把分析目录直接发给面试官**（含内网地址、数据量、故障细节）；
6. **证书与商户号**（`.pfx`/`.p12`/`truststore`/商户 ID）不要外发，也不要写进简历。

## 八、效率与工程实践

- **重活放后台**：全量扫描数千文件（尤其 19G 日志）会很慢，用后台任务并**单遍聚合**（一次解压 + 一次 awk 输出所有 KPI），避免逐关键字重扫；
- **采集与结论分离**：先落盘证据，再写结论，便于复核与增量更新；
- **人工修正在独立文件**：`evidence/_corrections.md` / `_audit-correction-log.md`，重跑采集器不会丢；
- **多智能体交叉审核**：把产物分给多个审核方（数字溯源 / 归属核对 / 规范检查 / 话术风险），效率与质量都远高于自查一遍。
